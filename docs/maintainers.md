## Download table in README.md

The block between `<!-- LATEST-RELEASE:START -->` and `<!-- LATEST-RELEASE:END -->` is generated by [`scripts/update_release.py`](../scripts/update_release.py) from the GitHub API (`pawlaszczyk/fqlite`, latest release). Do not edit it by hand.

The workflow [`.github/workflows/update-release.yml`](../.github/workflows/update-release.yml) runs

- daily,
- manually (*Actions → Update FQLite download links → Run workflow*),
- on a `repository_dispatch` event of type `fqlite-release`.

It commits `README.md` only if the table changed. Repository setting required: *Settings → Actions → General → Workflow permissions → Read and write permissions*.

While the latest FQLite release is older than 5.0, the table shows a note that Lighthouse is not yet included and points to building from source. The note disappears automatically with the first release ≥ 5.0 (`MIN_VERSION` in the script).

Run locally:

```bash
python3 scripts/update_release.py          # rewrite README.md
python3 scripts/update_release.py --check  # exit code 1 if README.md is out of date
```

### Optional: update immediately when FQLite is released

Add this job to the release workflow of the FQLite repository. It needs a fine-grained token with *Contents: read and write* on this repository, stored in FQLite as secret `LIGHTHOUSE_DISPATCH_TOKEN`:

```yaml
  notify-lighthouse:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -sS -X POST \
            -H "Authorization: Bearer ${{ secrets.LIGHTHOUSE_DISPATCH_TOKEN }}" \
            -H "Accept: application/vnd.github+json" \
            https://api.github.com/repos/pawlaszczyk/lighthouse/dispatches \
            -d '{"event_type":"fqlite-release"}'
```

Without it, the daily run picks up a new release within 24 hours.

## Checksums

`data/SHA256SUMS` lists all data files. Regenerate after any change:

```bash
cd data && find . -type f ! -name SHA256SUMS ! -name README.md ! -name LICENSE | sort | xargs shasum -a 256 > SHA256SUMS
```

The test-set manifests contain their own SHA-256; a test set must never change after it has been used for an evaluation.
